==============================================================
AI 타자 코치 (Windows 데스크톱 프로그램) 구현 명세
==============================================================

0. 문서 정보
- 작성일: 2026-11-18
- 상태: 구현 명세 v0.2 (1단계 시작 가능)
- 변경 이력
  v0.1: 1차 기획 (문장 데이터 준비 단계)
  v0.2: 제출 일정 항목 제외, 번호 정리, 부록 D(조합 엔진 규칙) 추가

1. 프로젝트 개요
- 한 줄 정의: 타자 습관(속도, 리듬, 오타 패턴, 손 뻗음)을 수집·분석해 약점을 찾고, 약점에 맞는 문장으로 집중 연습을 돕는 Windows 프로그램 [확정]
- 프로젝트 형태: 개인 프로젝트 [확정]
- 주제 배경: AI를 활용한 아이디어 중 AI 타자연습을 선택 [확정]
- 구현 원칙: 배운 Python, AI, GPT 등으로 간단히 동작 구현. 하드웨어 없이 소프트웨어만으로 구현 [확정]
- 핵심 가치: 구현이 쉽고, 재미있고, 실제로 쓸모 있을 것 [제안]
- 진로 연결: 데이터 분석(통계, 간단한 예측 모델)으로 전문성을 보완 [제안]
- 플랫폼: Windows 데스크톱 프로그램 우선. 웹 버전은 나중에 추가할 수 있음 [확정]
- 개발 방식: 바이브 코딩. 코드는 AI 코딩 도구가 작성 [확정]
- 시간 여유: 충분함 [확정]

2. 사용자 관점: 연습과 결과 흐름
- 연습 탭에서 카테고리를 고르면 목표 문장이 나온다 [확정]
- 한 문장을 다 치고 Enter를 누르면 제출되고 다음 문장이 나온다 [확정]
  (coding 카테고리의 줄바꿈 방식은 8번에서 정한다)
- 연습을 마치면 결과 요약을 보여 주고 저장한다 [제안]
- 결과 탭에서는 모든 그래프를 골라서 볼 수 있다 [확정]
- 결과 탭 왼쪽에는 피드백 카드 목록이 있다 [제안]
- 피드백 카드에는 주요 약점과 강점만 발췌해서 넣는다. 그래프는 전부 볼 수 있다 [확정]
- 카드의 '근거 보기'를 누르면 해당 그래프로 이동한다 [제안]
- 설정 탭에서 손목 기준점과 손가락 배정을 바꾼다 [확정]

3. 한글 입력 방식
- 한글은 앱이 자체적으로 자모를 조합한다. OS 한글 IME 결과는 쓰지 않는다 [확정]
- 이유: 받침, 쌍자음, Shift 실수, 한영 전환 실수 같은 자모 단위 분석을 하려면 필요하다 [확정]
- 참고 자료: 사용자가 이전에 만든 tkinter 한영 오입력 변환기. 2벌식 매핑, 자모 조합 상태 기계, 입력-출력 매핑 구조를 재사용한다 [확정]
- 참고 코드를 증분 입력 구조로 바꾼다. 백스페이스 처리와 키 단위 기록을 새로 만든다 [제안]
- 한글 자판: 2벌식 기본 [확정]. 3벌식은 나중에 옵션으로 추가 [예정]
- 입력창은 OS 한글 IME가 끼어드는 Text 위젯을 쓰지 않고 Canvas나 Label로 직접 그린다 [제안]
- 영문, 숫자, 기호는 물리 키 코드로 판정한다 [제안]

4. 키보드 형태와 좌표
- 데스크톱과 노트북을 구분하지 않는다. 표준 ANSI 풀배열 하나만 쓴다 [확정]
- 키 높이와 타건 깊이 차이는 구분하지 않는다. 이유: 구분 방법을 모르고 유의미한지도 불분명함 [확정]
- 키 간격 1u = 19.0mm. 모든 좌표는 mm 단위로 저장한다 [제안]
- 행 위치와 행 시작 오프셋 등 세부 수치는 부록 A에 적는다 [제안]

5. 손가락 배정과 손목 기준점
- 손가락 배정 기본값은 표준 타자 배치다 [확정]
- 사용자는 GUI에서 키를 클릭해 손가락을 바꿀 수 있다 [확정]
- 손목 기준점(수근관, 손목 바로 위 손바닥 위치)을 키보드 그림 위에서 클릭해 지정한다 [확정]
- 수근관은 키보드 면보다 아래에 있다. 이 높이 차를 dz(mm)로 입력받아 계산에 반영한다. 슬라이더로 조정한다 [확정]
- 키까지의 뻗음 거리: reach(k) = sqrt((k.x - wx)^2 + (k.y - wy)^2 + dz^2) [제안]
- 손목 기준점은 뻗음 거리 계산에만 쓴다. 손가락 배정을 자동으로 추정하는 데는 쓰지 않는다 [제안]
- 기본 기준점: x는 키보드 중앙, y는 스페이스 행 + 60mm, dz는 25mm [제안]

6. 문장 데이터
6-1. 출처와 저작권
- 저작권이 없는 문장, 비영리 사용이 가능한 문장, 가상으로 직접 만든 문장만 쓴다 [확정]
- 명언은 실존 인물 이름을 붙이지 않는다. 작자 미상이나 가상 인물 이름으로만 표기한다 [제안]
- 기사 문체는 실제 사건이 아니라 가상의 내용으로 쓴다 [제안]

6-2. 카테고리
- 다섯 가지: daily(일상대화), coding(코딩), article(기사), academic(학술), quote(명언풍) [확정]
- 1차에서는 quote만 활성화한다. 나머지는 파일을 미리 준비해 두고, 설정에서 켜서 나중에 연다 [확정]
- 활성 카테고리 목록은 config/categories.json에서 관리한다 [제안]

6-3. 생성과 저장
- 카테고리마다 10개씩 생성한다. 사용자도 직접 문장을 쓸 수 있다 [확정]
- 파일 형식: data/sentences/{카테고리}.jsonl, 한 줄에 문장 객체 하나 [제안]
- 객체 형식: {"id": "quote_001", "text": "문장"} [제안]
- id 형식: {카테고리}_{3자리}, 1부터 연속 번호. 사용자가 직접 쓴 문장은 manual_001처럼 붙인다 [제안]
- category와 tags 필드는 저장하지 않는다. 카테고리는 파일 이름이 알려주고, 특성은 코드가 계산한다 [확정]

6-4. 허용 문자
- 완성형 한글 음절(가~힣) [확정]
- 영문 A~Z, a~z, 숫자 0~9, 스페이스 [확정]
- 기호는 미국 배열에서 Shift를 포함해 한 번에 칠 수 있는 것만: ` ~ ! @ # $ % ^ & * ( ) - _ = + [ ] { } \ | ; : ' " , . < > / ? [제안]
- 금지: 한자, 외국어, 이모지, 말줄임표, 가운뎃점, 한국식 따옴표, 단독 자모 [확정]
- 줄바꿈은 coding 카테고리에서만 쓴다 [제안]

6-5. 길이 계산 [확정]
- 한국어 글자 수는 완성형 한글 음절, 영어 글자 수는 A-Z와 a-z를 센다. 숫자, 공백, 기호는 언어 판정에서 제외한다.
- 한국어 글자 수가 영어 글자 수 이상이거나 두 수가 모두 0이면 상한은 100자다. 영어 글자 수가 더 많으면 상한은 150자다.
- 길이는 공백과 기호를 포함한 원문 문자열의 글자 수다.
- 하한은 5자다. 상한을 넘는 문장은 연습에서 제외하고 경고한다.
- 라운드 총 길이와 전체 문장 평균도 같은 원문 길이를 쓴다. 세션 기준 평균은 실행 시점 전체 문장에서 계산한다.

6-6. 문장 특성 (태그 대신 수치로 계산)
- 태그를 파일에 저장하지 않는다. 문장을 불러올 때 코드가 아래 수치를 계산한다 [확정]
- 특성 목록과 계산식
  length: 원문 문자열 길이 (6-5 기준)
  eojeol: 공백 문자로 나눈 조각 수 (빈 조각 제외)
  jong_ratio: 종성이 있는 한글 음절 수 / 한글 음절 수
  complex_jong_ratio: 겹받침 음절 수 / 한글 음절 수
  complex_jung_ratio: 복합모음 음절 수 / 한글 음절 수
  double_ratio: 쌍자음(초성 또는 종성) 음절 수 / 한글 음절 수
  digit_ratio: 숫자 수 / 전체 글자 수
  alpha_ratio: 영문자 수 / 전체 글자 수
  symbol_ratio: 허용 기호 수 / 전체 글자 수
  newline_count: 줄바꿈 수
- 한글 음절이 없으면 한글 관련 비율은 0으로 둔다. 0으로 나누지 않는다 [확정]
- 한글 음절 분해: code = 문자코드 - 0xAC00, 초성 = code // 588, 중성 = (code % 588) // 28, 종성 = code % 28 [제안]
- 화면에 보여 줄 때만 기준값으로 "받침 많음" 같은 라벨을 붙인다 [제안]
- 기준값은 config/thresholds.json에 둔다. 코드에 상수로 박지 않는다 [확정]
- 받침 기준 0.4는 임시값. 분포를 보고 0.5로 올릴지 정한다 [미정]

7. 시스템 구조
7-1. 기술 스택
- 언어: Python 3.11 이상 [제안]
- GUI: tkinter와 ttk [제안]
- 그래프: matplotlib을 tkinter 화면에 넣는다 [제안]
- 저장: SQLite (표준 sqlite3) [제안]
- 분석: pandas, numpy [제안]
- AI: Gemini API (google-genai), 응답 형식을 고정해서 받는다 [예정]
- 테스트: pytest [제안]
- 배포: PyInstaller로 Windows 실행 파일 [예정]

7-2. 폴더 구조 (폴더 이름은 [미정])
typing_coach/ (또는 Gwaze/)

  core/

7-3. 키 입력 처리 [제안]
- 키 판정은 tkinter 이벤트의 물리 키 코드(keycode) 기준. 한영 상태와 무관하게 같은 결과
- 키를 누른 채 반복되는 입력(auto-repeat)은 기록에서 뺀다
- 백스페이스는 자모 단위로 지운다 (부록 D 참고)
- 목표 문장 비교는 음절을 자모로 분해한 뒤 자모 단위로 한다. 받침 오타를 위치별로 기록하기 위해서다
- 입력 한 번마다 시각(누름과 뗌), 키, Shift 여부, 동작 종류, 정답 여부를 기록한다

8. 줄바꿈과 제출 키 [미정]
- 일반 카테고리: Enter로 제출하고 다음 문장으로 넘어간다 [확정]
- coding 카테고리는 아래 둘 중 하나를 정해야 한다 [미정]
  A안(제안 추천): Enter는 줄바꿈, Ctrl+Enter는 제출
  B안: 줄 단위 제출. Enter를 누를 때마다 다음 줄로 넘어간다. 모든 카테고리에서 Enter의 뜻이 같아진다
- 공통 규칙 [제안]: 자동 들여쓰기 금지, Tab 입력 무시, 목표 완성 시 자동 제출하지 않음
- coding 카테고리는 이 방식이 정해진 뒤에 활성화한다 [확정]

9. 지표 목록 [제안]
- 시작 지연: 문장 표시 후 첫 키 누름까지 시간
- 타속: 자모 기준 CPM, 전체와 어절별
- 어절 시작 지연과 어절 내부 간격의 중앙값
- 키 간격(IKI): 2000ms 이상은 멈춤으로 분류해서 리듬 계산에서 뺀다
- 리듬 변동계수(CV): 표준편차 / 평균
- 키별 오타율, 자모 위치별(초성·중성·종성) 오타율, 받침 유무별 오타율
- 혼동 쌍: (목표 키, 입력 키) 횟수
- 오타 방향: 목표 키 대비 입력 키의 상하좌우 벡터(mm)
- 수정 시간: 오타 누름부터 올바른 입력까지
- 공백 누락 수
- 중복 입력 비율: 이전 키를 떼기 전에 누른 경우, 또는 같은 키를 50ms 이내 연속
- 뻗음 그룹별 오타율: 1u 미만, 1~2u, 2u 이상
- 손가락별 오타율
- 전반과 후반 타속 비율 (피로 지표)
- 오타 연쇄 구간: 60초 동안 오타 3회 이상, 그 직후 5키의 평균 간격

10. 탐지기 (약점과 강점) [제안]
10-1. 약점 유형
  1. 단어 기억 부족: 어절 시작 지연이 어절 내부 간격보다 훨씬 긴 경우 [사용자 예시]
  2. 받침 오타: 받침 있는 음절의 오타율이 없는 음절보다 높은 경우 [사용자 예시]
  3. 띄어쓰기 생략 후 수정: 공백을 빠뜨리고 백스페이스로 고치는 경우 [사용자 예시]
  4. 손이 덜 뻗음: 뻗음 거리가 먼 키에서 오타가 많은 경우 [사용자 예시]
  5. 두 키 동시 또는 중복 입력: 중복 입력 비율이 높은 경우 [사용자 예시]
  6. 입력 속도가 일정하지 않음: IKI 변동계수가 큰 경우 [사용자 예시]

10-3. 공통 규칙 [제안]
- 기준선 세션(처음 3세션)에는 카드를 만들지 않는다

D-2. 조합 규칙
- 초성 → 중성 → 종성 순서로 음절을 만든다.
- 자음 뒤에 모음이 오면 음절이 된다. 모음 뒤에 자음이 오면 종성 후보가 된다.
- 종성 뒤에 모음이 오면 종성을 다음 음절의 초성으로 옮긴다.
  겹받침이면 뒤쪽 자음만 옮기고, 앞쪽은 현재 음절에 남긴다.
- 자음 두 개가 연속되고 앞 자음이 종성이 될 수 있으면, 뒤 자음은 새 음절의 초성이 된다.
- 쌍모음과 겹받침은 조합이 가능할 때만 합친다. 불가능하면 새 음절로 나눈다.
- 음절을 만들 수 없는 자모는 단독 자모로 출력한다.
- 한글이 아닌 문자(영문, 숫자, 기호, 공백)는 조합 중인 음절을 먼저 확정한 뒤 그대로 출력한다.
- 조합기 인터페이스
  feed(문자, 키 번호, 시각): 문자 하나를 입력한다
  backspace(시각): 자모 한 개 단위로 지운다
  text(): 현재 전체 문자열
  trace(): 출력 글자마다 기여한 입력 이벤트 번호 목록을 돌려준다

D-3. 백스페이스 규칙 (자모 단위)
- 종성이 겹받침이면 뒤쪽 자모만 지운다. 예: 갉 → 갈
- 종성이 하나이면 종성을 지운다. 예: 간 → 가
- 중성이 겹모음이면 뒤쪽 모음만 지운다. 예: 과 → 고
- 중성을 지운 뒤 초성만 남으면 초성을 유지한다. 예: 가 → ㄱ
- 초성까지 지우면 음절을 삭제한다
- 한글이 아닌 문자는 한 글자씩 지운다
- 백스페이스로 지운 내용도 기록에 "지움" 이벤트로 남긴다
