문장 특성 태그 규칙
====================

문장을 읽을 때 아래 규칙으로 tags를 계산한다.
태그는 문장 내용에서 계산하며 파일과 세션 기록에는 저장하지 않는다.
1. 데이터 형식
-------------

각 문장은 다음 필드를 가진 JSON 객체로 저장한다.

{
  "id": "quote_001",
  "category": "quote",
  "text": "분석할 문장"
}

앱은 아래 태그 목록 중 해당하는 태그를 계산하며, 2절의 순서를 사용한다.


2. 태그 목록과 출력 순서
-----------------------

1) 받침많음
2) 겹받침
3) 복합모음
4) 쌍자음
5) 어절많음
6) 숫자포함
7) 영문포함
8) 기호포함
9) 긴문장
10) 짧은문장
11) 줄바꿈포함


3. 기준값
---------

받침많음 비율: 0.4 이상
어절많음 개수: 6개 이상
긴문장 글자 수: 공백 포함 45자 이상
짧은문장 글자 수: 공백 포함 20자 이하

글자 수는 문장 text의 문자 수로 계산한다. 공백과 문장부호도 글자 수에 포함한다.
어절 수는 text를 공백 등 공백 문자 기준으로 나누었을 때 비어 있지 않은 조각의 수다.


4. 한글 분석
------------

완성형 한글 음절은 가(U+AC00)부터 힣(U+D7A3)까지다.
한글 음절을 다음과 같이 초성, 중성, 종성 인덱스로 분해한다.

code = 문자 코드 - 0xAC00
초성 인덱스 = code // 588
중성 인덱스 = (code % 588) // 28
종성 인덱스 = code % 28

받침많음:
완성형 한글 음절 중 종성이 있는 음절 수를 한글 음절 전체 수로 나눈다.
이 비율이 0.4 이상이면 붙인다. 한글 음절이 없으면 비율은 0으로 본다.

겹받침:
종성 인덱스가 아래 집합에 하나라도 포함되면 붙인다.
{3, 5, 6, 9, 10, 11, 12, 13, 14, 15, 18}

복합모음:
중성 인덱스가 아래 집합에 하나라도 포함되면 붙인다.
{9, 10, 11, 14, 15, 16, 19}

쌍자음:
초성 인덱스가 {1, 4, 8, 10, 13} 중 하나이거나,
종성 인덱스가 {2, 20} 중 하나인 음절이 있으면 붙인다.


5. 문자와 문장 단위 분석
------------------------

숫자포함:
ASCII 숫자 0부터 9 중 하나라도 있으면 붙인다.

영문포함:
ASCII 영문자 A부터 Z 또는 a부터 z 중 하나라도 있으면 붙인다.

기호포함:
아래 허용 기호 중 하나라도 있으면 붙인다.
` ~ ! @ # $ % ^ & * ( ) - _ = + [ ] { } \ | ; : ' " , . < > / ?

긴문장:
공백을 포함한 text의 문자 수가 45자 이상이면 붙인다.

짧은문장:
공백을 포함한 text의 문자 수가 20자 이하이면 붙인다.

줄바꿈포함:
text에 줄바꿈 문자 LF(U+000A)가 포함되면 붙인다.


6. 허용 문자 검사
----------------

다음 문자만 허용한다.
- 완성형 한글 음절: 가부터 힣까지
- ASCII 영문자 A-Z, a-z
- ASCII 숫자 0-9
- 일반 스페이스
- 줄바꿈 LF(U+000A)
- 5절에 나열된 허용 기호

이 목록에 없는 문자가 있으면 해당 문장을 규칙 위반으로 표시한다.
한글 단독 자모, 한자, 그 밖의 외국 문자, 이모지, 탭, 캐리지 리턴,
목록에 없는 문장부호와 특수문자는 허용하지 않는다.


7. 적용 및 검증
---------------

새 문장을 JSONL 파일에 추가한 뒤, 새 문장뿐 아니라 수정된 문장의 tags도 계산 결과를 확인한다.
tags는 위 목록에 있는 이름만 사용하고, 반드시 태그 출력 순서를 따른다.
계산 결과를 확인한 뒤 JSON 파싱 여부, 각 객체의 id/category/text 필드,
ID의 연속성과 중복 여부, 허용되지 않은 문자의 존재 여부를 확인한다.

태그 기준값을 바꾸려면 이 파일과 태그 계산 코드의 기준값을 함께 변경한다.
