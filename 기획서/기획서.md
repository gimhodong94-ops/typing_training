# AI 타자 코치 기획서

- 문서 성격: 사용자가 나중에 직접 수정하는 마스터 기획서
- 작성 기준일: 2026-11-20
- 프로젝트 형태: 개인 과제용 Windows 데스크톱 프로그램
- 제안서 제출: 2026-11-24
- 최종 발표: 2026-12-08
- 현재 프로그램 상태: 설계와 구현이 동시에 진행 중이며, 원문 기획 메모와 실제 동작을 모두 반영한다.

## 1. 프로젝트 요약

AI 타자 코치는 사용자의 타자 속도, 오타, 리듬, 키 위치와 문장 특성을 기록한 뒤 약점을 분석하고, 약점에 맞춘 연습 문장과 피드백을 제공하는 Windows 프로그램이다.

### 목적

- 한글과 영어를 포함한 타자 습관을 수집한다.
- 키별 오타, 느린 키, 한영 전환 실수, 리듬 변화를 분석한다.
- 규칙 기반 분석과 선택한 AI 제공자의 피드백을 결합한다.
- 약점에 맞춘 문장으로 다음 연습을 진행한다.

### 핵심 원칙

- 하드웨어 센서를 사용하지 않고 키보드 입력만으로 분석한다.
- 문장 특성 태그는 파일에 저장하지 않고 문장 내용에서 계산한다.
- 기준값은 가능한 한 설정과 규칙 파일로 관리한다.
- AI가 실패해도 로컬 분석과 기본 연습은 계속 동작한다.
- 현재 버전은 Windows 데스크톱 중심이다.

## 2. 확정 구현 방향

### 플랫폼

- 주 플랫폼: Windows 데스크톱 프로그램
- 화면 기술: React 기반 데스크톱 화면
- 런타임: Electron
- 일반 브라우저판은 과거 소스로 보관하며 현재 제품 개발 범위에서 제외한다.
- 기존 웹판 소스와 압축본 위치
  - 폴더: `archive/legacy-web/`
  - 압축본: `archive/legacy-web.zip`

### 화면 흐름

1. 시작 화면
2. 연습 화면
3. 결과 화면
4. 설정 또는 AI 설정 화면
5. 약점 연습 및 다음 기록으로 이어지는 흐름

## 3. 시작 화면

- 키보드 종류를 선택한다.
  - 데스크톱
  - 노트북
- 다음 키 표시 여부를 선택한다.
- 기본 30라운드 연습을 시작한다.
- 최근 연습 기록 목록을 보여준다.
- 사용자가 과거 기록을 선택해 다시 볼 수 있게 한다.
- AI 제공자와 모델을 선택하고 API 키를 저장할 수 있다.

### 키보드 종류 처리

- 데스크톱과 노트북은 기록 필드만 구분한다.
- 키 배열과 판정 좌표는 기본형을 사용한다.
- 노트북 기준의 별도 키 배열은 아직 구현하지 않는다.

## 4. 연습 화면

### 기본 연습 규칙

- 한 문장을 입력하면 한 라운드가 끝난다.
- 문장 수와 라운드 수는 같다.
- 기본값은 30라운드다.
- 문장을 모두 올바르게 입력한 뒤 Enter를 눌러야 다음 라운드로 넘어간다.
- 문장을 다 쳤다고 자동으로 다음 라운드로 넘어가지 않는다.
- 오타가 있으면 Backspace로 지워야만 올바르게 진행할 수 있다.

### 화면 구성

- 위쪽: 목표 문장
- 아래쪽: 사용자가 조합한 입력 결과
- 숨은 입력창에 포커스를 둔다.
- 한글은 2벌식 자모 조합을 고려해 사용자의 실제 입력을 표시한다.
- 다음 키 표시 설정이 켜져 있으면 누를 키를 안내한다.

### 입력 판정

판정은 다음 요소를 함께 확인한다.

- 누른 물리 키 위치: `event.code`
- 한글/영문 입력 상태
- 목표 문자
- 백스페이스와 수정 동작
- 키 누름 시각 및 간격

#### 한글 판정

- 한글 자모 키는 한글 IME 상태여야 한다.
- 한글 상태 판정은 키다운의 `key`가 `Process`인 조건을 활용한다.
- 한글 자모 목표를 영문 상태로 입력하면 오입력 종류에 `한/영 상태`를 기록한다.

#### 영문 판정

- 영문 글자 키는 영문 입력 상태여야 한다.
- 영문 목표를 한글 상태로 입력하면 오입력 종류에 `한/영 상태`를 기록한다.

#### 한영과 무관한 입력

다음 입력은 한/영 상태와 관계없이 판정한다.

- 숫자
- 스페이스
- 기호

## 5. 기록 데이터

### 키 입력마다 저장할 정보

- 입력 시각
- 누른 키
- 눌러야 할 키
- 오입력 종류
- 목표 키와의 물리적 거리
- 오타 방향
- 한영 상태
- 정답 여부
- 백스페이스 또는 수정 여부

### 저장 방식

- 데스크톱 앱에서는 브라우저 저장소 형식으로 최근 기록을 보관한다.
- 최근 최대 8회 기록을 보관한다.
- 한 세션이 끝나면 세션 요약과 피드백 정보를 함께 저장한다.
- 설정 변경 이후에도 과거 기록 해석이 가능하도록 세션별 설정 정보를 함께 보관한다.

### 기존 문서의 저장 방식과 실제 상태

- 초기 기획서에는 SQLite 저장을 제안했지만, 현재 구현은 브라우저 저장소를 사용한다.
- 즉, 첫 구현 기준은 로컬 PC의 앱 저장소이다.
- SQLite로 전환할지는 추후 기능 완성도와 데이터 보관 필요성을 보고 결정한다.

## 6. 문장 데이터

### 문장 저장 형식

- 위치: `data/sentences/*.jsonl`
- 한 줄에 문장 객체 하나
- 필드 순서: `id`, `category`, `text`
- 태그는 저장하지 않는다.
- 한 줄 예시:

```json
{"id":"quote_001","category":"quote","text":"분석할 문장"}
```

### 문장 생성 규칙

- 카테고리별 문장을 준비한다.
- 현재 활성 카테고리는 명언풍 문장이다.
- 사용자가 직접 문장을 추가할 수 있도록 한다.
- 사용자가 직접 만든 문장의 ID는 `manual_001` 같은 형식을 사용한다.

### 카테고리

- 일상 대화: daily
- 코딩: coding
- 기사: article
- 학술: academic
- 명언풍: quote

코딩 카테고리와 다른 카테고리의 실제 활성화는 아직 구현하지 않는다.

## 7. 문장 문자와 길이 규칙

### 허용 문자

- 완성형 한글 음절: 가~힣
- 영문: A~Z, a~z
- 숫자: 0~9
- 일반 스페이스
- 미국 배열에서 Shift와 함께 입력할 수 있는 허용 기호
- 코딩 카테고리의 줄바꿈은 별도 규칙을 정한 뒤 활성화한다.

### 금지 문자

- 한자
- 외국어 문자
- 이모지
- 말줄임표
- 가운뎃점
- 한국식 따옴표
- 탭
- 캐리지 리턴
- 단독 자모
- 목록에 없는 특수문자

### 길이 제한

- 한국어 우세 문장 상한: 100자
- 영어 우세 문장 상한: 150자
- 하한: 5자
- 문자 수는 공백과 기호를 포함한 원문 문자열 길이를 사용한다.
- 한국어와 영어 수치가 같거나 한국어가 0개이고 영어도 0개이면 한국어 우세로 본다.

## 8. 라운드 구성

- 라운드 1개는 문장 1개를 완전히 치고 Enter로 제출하는 한 번의 연습이다.
- 기본 라운드 수는 30개이다.
- 임시 라운드 구성은 `tools/make_round.py` 규칙을 따른다.
- 중복 문장을 사용하지 않는다.
- 30개 문장의 총 글자 수는 전체 문장 평균 길이의 30배를 기준으로 ±30% 안에 있어야 한다.
- 범위를 벗어나면 전체 문장 선택을 다시 수행한다.
- 현재 화면의 문장 선택 구현은 Python 임시 도구와 같은 규칙을 유지한다.

### 추후 방향

- AI가 사용자의 약점에 맞춰 문장을 생성하고 라운드를 구성한다.
- 약점 연습 문장은 10개를 기본으로 한다.
- 생성 문장은 문자 규칙, 길이 상한, 약점 근거와 총 글자 수 범위를 만족해야 한다.

## 9. 문장 특성 계산

태그는 문장 내용에서 계산하며 다음 용도로만 사용한다.

- 결과 화면의 문장 특성별 속도 표시
- 약점 요약
- AI 요약 데이터
- 약점 연습 문장 생성 근거

태그나 특성은 문장 JSON과 세션 기록에 저장하지 않는다.

### 계산 특성

- 원문 길이
- 어절 수
- 받침 비율
- 겹받침 비율
- 복합모음 비율
- 쌍자음 비율
- 숫자 비율
- 영문 비율
- 기호 비율
- 줄바꿈 수

### 대표 태그 기준

- 받침많음: 받침 비율 0.4 이상
- 어절많음: 어절 6개 이상
- 긴문장: 공백 포함 45자 이상
- 짧은문장: 공백 포함 20자 이하
- 숫자포함
- 영문포함
- 기호포함
- 줄바꿈포함

정확한 태그 규칙과 기준값은 `tag_rules.txt`와 설정 파일을 기준으로 한다.

## 10. 한글 입력 엔진 방향

- 한글은 앱이 2벌식 자모 조합을 직접 처리한다.
- OS IME의 완성형 텍스트 결과만을 전부 믿지 않는다.
- 쌍자음, 겹받침, 복합모음, 백스페이스와 한영 전환을 자모 단위로 분석한다.

### 조합 원칙

- 초성 → 중성 → 종성 순서로 음절을 만든다.
- 겹받침과 쌍모음은 가능한 조합일 때만 합친다.
- 종성 뒤에 모음이 오면 종성을 다음 음절의 초성 후보로 넘긴다.
- 한글이 아닌 문자는 조합 중인 음절을 먼저 확정한 뒤 그대로 추가한다.

### 백스페이스 원칙

- 종성이 겹받침이면 뒤쪽 자모만 먼저 지운다.
- 종성이 하나이면 종성을 지운다.
- 중성이 겹모음이면 뒤쪽 모음만 지운다.
- 초성까지 지우면 한글 음절을 삭제한다.
- 지운 동작도 수정 이벤트로 기록한다.

## 12. 약점 분석과 피드백

약점 카드는 규칙 기반 탐지기와 강점 분석으로 만든다.

### 약점 유형 후보

1. 어절 시작 지연이 어절 내부 간격보다 큰 경우
2. 받침이 있는 음절의 오타가 많은 경우
3. 공백을 빼고 백스페이스로 수정하는 경우
4. 키보드에서 멀리 뻗는 위치의 오타가 많은 경우
5. 중복 입력이 많은 경우
6. 타이핑 속도 변동이 큰 경우
7. 오타가 반복된 직후 속도가 떨어지는 경우
8. 쌍자음과 Shift 실수
9. 한영 전환 실수
10. 복합모음 입력 지연

쌍자음과 Shift, 한영 전환, 복합모음은 현재 우선 구현 범위에서 제외하거나 별도 개선 대상으로 둔다.

### 강점 후보

- 충분한 시도의 키 중 오타율이 0인 키가 여러 개일 때
- 후반 타속을 일정 비율 이상 유지할 때

### 카드 구성

- 제목
- 근거 수치
- 가능한 원인 가설
- 다음 연습 체크 포인트
- 조언
- 근거를 확인할 그래프 위치

### 카드 제한

- 기준 세션 전에는 약점 카드를 만들지 않는다.
- 표본이 부족하면 카드를 만들지 않는다.
- 약점은 최대 3개까지만 보여준다.
- 강점은 필요한 범위에서 요약한다.
- 중복 탐지기 유형은 한 세션에 카드 1개만 만든다.

- 키별 오타, 느린 키, 한영 상태 오입력 결과가 표시된다.
- 문장 특성이 태그 파일에 저장되지 않는다.
- 규칙 위반 문장은 로딩이나 생성 검증에서 제외되거나 경고된다.
- AI가 실패해도 일반 피드백과 약점 연습을 계속 사용할 수 있다.
- Windows 데스크톱 빌드와 설치 파일 실행을 확인할 수 있다.

[3] 화면 흐름
3-1. 시작 화면: 라운드 수(10/20/30) 선택, 다음 키 표시 켜기/끄기, 카테고리 체크박스(활성 카테고리만), 연습 시작, 최근 기록 목록, AI 설정(제공자, 모델, 키 저장/삭제).
3-2. 연습 화면: 위쪽에 목표 문장, 아래쪽에 앱이 조합한 입력 결과, 진행 표시("라운드 3 / 30"), 일시정지 버튼.
3-3. 결과 화면: 요약 → 약점 카드 → 자세히 보기 → 약점 연습 버튼.
3-4. 설정: 손목 기준점, dz, 손가락 배정, 표준 배치로 되돌리기.

[4] 연습 규칙과 판정
4-1. 진행
  - 한 문장을 모두 올바르게 입력한 뒤 Enter를 눌러야 다음 라운드로 간다. 자동으로 넘어가지 않는다. [확정]
  - 오타가 있으면 Backspace로 지워야 올바른 상태가 된다. [확정]
  - Tab은 입력으로 처리하지 않는다.
4-2. 입력 판정 (키 하나마다)
  - 물리 키(event.code)가 기대 키와 같아야 한다.
  - 필요한 Shift 상태가 같아야 한다. 자모가 같아도 Shift가 다르면 오답이다. 예: 목표 ㅔ(P)에 ㅖ(Shift+P)는 오답이고 "Shift 실수"다.
  - 문자 키(A~Z)는 한/영 상태도 같아야 한다. 숫자, 스페이스, 기호는 한/영 상태를 보지 않는다.
  - 한/영 상태는 추정값이다: isComposing, key === "Process", keyCode === 229. 확신할 수 없으면 오답으로 처리하지 않고 "판정 불가"로 기록한다. [제안]
  - auto-repeat는 Backspace를 제외하고 무시한다.
4-3. 오입력과 오타 에피소드
  - 오입력 종류: 다른 키 / Shift 실수 / 한/영 상태 / Caps Lock / 초과 입력. (D5)
  - 오타 에피소드 = 첫 오입력부터 그 위치 이후가 모두 지워지고 다시 올바르게 채워질 때까지의 구간이다.
  - 각 오입력 이벤트에 episodeId와 episodeRole(first | cascade)을 붙인다. 에피소드의 첫 오입력이 first, 같은 에피소드의 나머지 오입력이 cascade다. [제안]
  - 낱자 하나가 빠지면 뒤 키들이 줄줄이 틀린 것으로 판정된다. 이 연쇄가 약점 통계를 왜곡하지 않도록, 확신도와 약점 판정에 쓰는 통계(키별, 손가락별, 묶음별)는 first만 센다. 화면의 "틀린 입력 N번"과 정확도는 D5대로 전체를 센다. [제안]
  - 에피소드 분류(정렬 분류): 한 에피소드의 입력 구간과 기대 구간을 편집 거리로 정렬해 치환 / 누락 / 초과 / 전치 / 모호로 라벨을 붙인다. 같은 위치끼리 한 칸씩 비교하지 않는다.
  - 불변 조건: 정렬 분류의 n = 에피소드 수 ≤ 오입력 수. Backspace는 분류 대상이 아니다. 이 조건이 깨지면 테스트가 실패해야 한다.
  - [확인] 최근 결과에서 "초과 입력"이 79~82로 Backspace 81회와 거의 같았고, 두 세션 모두 n=85였다. 현재 정렬 분류가 Backspace나 지워진 키를 초과로 세고 있는지 코드로 확인하고, 위 불변 조건에 맞게 고친다.
4-4. 한/영 상태 오입력은 D6대로 오답이다. 결과에는 "한/영 상태가 달랐던 입력 N번"으로 따로 표시한다.
4-5. 자주 틀린 키 목록
  - 같은 "목표 키 → 실제 키" 쌍이 5회 이상일 때만 목록에 넣는다. 설정: weakKeyMinimumSamples.
  - 목록이 비어 있어도 오타가 없는 것이 아니다. 문구를 "같은 실수가 5번 이상 반복된 키 조합은 없어요. 오타는 N번 있었지만 여러 키에 흩어져 있어요."로 바꾼다. "틀린 기록이 없어요"는 쓰지 않는다.
4-6. 정확도 두 가지 [D8, 정의는 제안]
  - 용어: 시도 = 문자 키 keydown 1회(Backspace, Shift, Enter, auto-repeat 제외). 오입력 = 4-3.
  - 타건 정확도(A) = 정타 시도 수 / 전체 시도 수. Enter 전에 고친 오타도 오류에 포함한다. [확인] 현재 정확도가 이미 이렇게 계산되는지 코드로 확인하고 보고한다.
  - 지우기 포함 정확도(B) = 1 − (오입력 수 + 잘못 지움 수) / (전체 시도 수 + 잘못 지움 수)
  - 잘못 지움 = Backspace가 올바른 입력(정타)을 지웠고, 그 시점의 입력창에 지워지지 않은 오타가 하나도 없었던 경우. 입력창 앞쪽에 오타가 있어서 그 오타에 닿으려고 정타를 지우는 것은 필요한 지우기이므로 세지 않는다.
  - 한글은 자모 단위로 지운다. 지운 자모가 그 위치의 정타였는지로 판정한다.
  - Backspace 이벤트에 removedUnit, removedWasCorrect, needed(필요한 지우기였는지) 필드를 기록한다.
  - 결과 화면: 요약 줄에는 A를 쓴다. "지우기 포함 정확도 B"는 자세히 보기에 표시한다. [제안]
4-7. 일시정지 [확정]
  - 연습 화면의 "일시정지" 버튼을 마우스로 누를 때만 정지/재개한다. 단축키는 없다.
  - 정지 중: 타이머와 타속 계산을 멈추고, 키 입력을 무시하며 기록하지 않고, 목표 문장과 입력 내용을 가린다. 버튼은 "재개"로 바뀐다.
  - 한글 조합 중인 음절은 정지 전 상태를 유지한다. 확정하거나 지우지 않는다.
  - 재개 후 첫 키 입력에는 resumedAfterPause 표시를 남긴다. 한 문장에서 여러 번 정지할 수 있다.
  - 정지 구간은 {seq, startMs, endMs}로 세션에 저장한다.
  - 정지 경계를 가로지르는 키 간격은 리듬 계산에서 뺀다. 재개 직후 첫 키 지연은 따로 기록한다. 시작 지연과 타속에서 정지 시간을 뺀다.
  - 정지 전후 차이를 판정하는 탐지기는 만들지 않는다. 데이터만 남긴다.
4-8. 다음 키 표시(힌트) [D7]
  - 켜짐/꺼짐을 세션에 기록한다(hintOn).
  - 비교, 누적, 확신도 계산은 같은 hintOn 세션끼리만 한다. 다른 설정의 세션은 "설정이 달라 비교하지 않아요"로 표시한다.
4-9. 뻗음 거리와 방향 [제안]
  - 뻗음 거리 = 가까운 쪽 손목 기준점(왼쪽/오른쪽)에서 키까지의 3차원 거리(dz 포함). 단위는 "칸"(1칸 ≈ 19mm)이다.
  - 구간 경계: 입력 가능한 모든 키의 뻗음 거리를 모아 3분위로 나눠 가까움/보통/멂으로 부른다. 경계값은 키보드 배치와 설정에서 계산하고 세션에 함께 저장한다. 세션 데이터로 계산하지 않는다. (1칸, 2칸 고정 경계는 쓰지 않는다. 최근 결과에서 936개 중 936개가 "2칸 이상"에 몰렸다.)
  - 방향 통계는 같은 손 안의 인접 오타(키 거리 ≤ 2칸)만 대상으로 한다. 손을 넘은 오타와 스페이스로 잘못 간 오타는 "손을 넘은 오타"로 따로 센다. 평균 방향은 큰 값에 끌려가므로 중앙값을 쓴다.
  - towardWrist = (실제 키 − 목표 키)와 (손목 − 목표 키)의 내적이 0보다 큰 비율. metricDefinitions에 정의를 적는다.

[5] 한글 입력 엔진
- 화면의 한글은 앱이 직접 조합한다(Play.tsx의 buf → hangul.ts composeTyped). OS IME의 완성 결과를 쓰지 않는다. [확정, Codex 확인됨]
- 한/영 상태 판정만 IME 이벤트 신호를 쓴다.
- 조합: 초성 → 중성 → 종성. 종성 뒤에 모음이 오면 종성(겹받침이면 뒤쪽)을 다음 음절 초성으로 넘긴다. 쌍모음과 겹받침은 가능할 때만 합친다.
- 백스페이스: 겹받침이면 뒤쪽 자모만, 단일 받침이면 받침, 겹모음이면 뒤쪽 모음, 초성까지 지우면 음절 삭제. 지운 동작도 이벤트로 기록한다.
- 회귀 테스트(반드시 유지): rk→가, rks→간, rkqt→값, rkfr→갉, rhk→과, Rna→꿈, rkfr+Backspace→갈, rhk+Backspace→고.
- 회귀 테스트: 한국어 뒤에서 스페이스가 두 번 입력되는 버그(0.1.7에서 수정)가 다시 생기지 않는다. IME 중복 신호가 있는 스페이스만 걸러내고, 빠른 연속 일반 스페이스는 지우지 않는다.

[6] 기록 데이터
6-1. 키 입력 이벤트 [확인] 아래는 현재 확인된 필드와 이번에 추가할 필드다. 실제 이름이 다르면 매핑표를 보고한다.
  기존: t, code, kind, pos, shift, caps, exp, expShift, ok, err, dx, dy, isNext, isPrev, ime, sessionMs, pauseSeq, resumedAfterPause, resumeDelayMs, keyupT, targetKey, typedKey, targetShift, typedShift, shiftSide, nextTargetKey, targetPressedLaterOk
  추가: episodeId, episodeRole, removedUnit, removedWasCorrect, removedNeeded, imeState(확실/추정/판정 불가)
6-2. 키업 처리 [제안]
  - keyup이 없는 입력이 한 건이라도 있으면 키 타이밍 전체를 "집계 안 됨"으로 처리하는 지금 방식을 바꾼다.
  - keyup이 기록된 입력의 비율(keyupCoverage)을 계산해 표시한다. 비율이 keyupCoverageMin(임시 0.9) 이상이면 keyup이 있는 입력만으로 집계한다. 미만이면 "집계 안 됨"으로 둔다.
6-3. 세션 객체
  기존: id, rounds, roundCount, pauses, schemaVersion 2, feedback, 설정 정보
  추가(schemaVersion 3): hintOn, reachCutoffs, wristAnchors, dz, fingerMapVersion, accuracyA, accuracyB, wrongErase 횟수
6-4. 세션 요약 객체(최근 50세션 보관, D28) [제안]
  - 키별 {k, n}, 손가락별 {k, n}, 손별, 줄별, 한글 위치별(초/중/종성), 받침 유무별, 공백, Shift 조합, 정렬 분류 개수, 에피소드 수, 정확도 A/B, 첫 키 지연 평균, 정지 정보, hintOn, 설정 스냅샷.
  - 원본 이벤트는 최근 8세션만 보관한다. 요약은 원본이 삭제돼도 남는다.
  - 기존 세션(schemaVersion 2 이하)은 새 필드가 없으므로 해당 항목을 "집계 안 됨"으로 둔다. 0으로 쓰지 않는다.

[7] 문장과 라운드
7-1. 문장 파일: data/sentences/{카테고리}.jsonl, 한 줄에 {"id", "category", "text"}. tags 필드는 없다. [확정]
7-2. id 형식: {카테고리}_{3자리}. 사용자가 직접 쓴 문장은 manual_001. category 값이 파일 이름과 다르면 경고한다. [제안]
7-3. 허용 문자: 완성형 한글, A-Z a-z, 0-9, 스페이스, 기호 ` ~ ! @ # $ % ^ & * ( ) - _ = + [ ] { } \ | ; : ' " , . < > / ?. 금지: 한자, 외국어, 이모지, 말줄임표, 가운뎃점, 한국식 따옴표, 탭, 캐리지 리턴, 단독 자모. 줄바꿈은 coding에서만 허용하며 coding은 줄바꿈 방식이 정해질 때까지 열지 않는다. [확정]
7-4. 길이: D11. 위반 문장은 로딩에서 제외하고 경고한다.
7-5. 세션 구성: D10. 기준 평균은 data/sentences 전체의 같은 방식 길이 평균을 실행할 때마다 계산한다. 한 세션 안에서 같은 문장은 두 번 쓰지 않는다. 덜 쓰인 문장을 먼저 고른다(사용 횟수는 저장된 기록에서 센다). 문장 풀이 라운드 수보다 적으면 사용 횟수가 적은 순서로 다시 쓴다.
7-6. 카테고리: daily, coding, article, academic, quote. 지금은 quote만 열려 있다. config/categories.json의 enabled 목록으로 열고 닫는다. [확정]
7-7. 문장 특성(계산만 한다): length, eojeol, jong_ratio, complex_jong_ratio, complex_jung_ratio, double_ratio, digit_ratio, alpha_ratio, symbol_ratio, newline_count. 표시용 라벨 기준(받침많음 0.4 등)은 config에 둔다. [확정]
7-8. tools/*.py(check_sentences, summary, make_round)는 유지한다. 규칙을 바꾸면 같은 규칙으로 맞춘다.

[8] 지표 정의
8-1. 속도: 분당 타수(정지 시간 제외), 라운드별 타속, 어절별 타속, 첫 키 지연(문장 표시 → 첫 keydown, 정지 제외).
8-2. 키 간격(IKI): 연속 문자 입력 사이 시간. 정지 경계를 가로지르는 간격은 뺀다. 중앙값, 사분위 범위, 2000ms 초과 횟수(longGap)를 표시한다. 고정 컷오프는 판정에 쓰지 않는다.
8-3. 오타율: 목표 키별 {k, n}. k는 first 에피소드 오입력만 센다(4-3). 화면의 "틀린 입력 N번"은 전체다.
8-4. 묶음: 손가락(9), 손(좌/우), 줄(숫자/윗줄/가운뎃줄/아랫줄/스페이스), 한글 위치(초/중/종성), 받침 유무, 뻗음 구간(가까움/보통/멂), Shift 조합, 공백. Shift 조합 글자는 손가락과 손 묶음에서 뺀다.
8-5. 수정: 오타부터 올바른 입력까지 걸린 시간, 같은 자리 재오타 횟수, 오타를 고치지 않고 계속 친 입력 수(최대 연속).
8-6. 같은 손 연속 vs 번갈아 입력의 키 간격 중앙값.
8-7. 확률 구간: 모든 오타율에 Wilson 95% 구간을 계산한다. 화면에서는 "실제 오타율은 대략 A~B% 사이로 보여요"라고 쓴다.

Phase 2 (필수)
 1 낱자 하나 빠짐: 에피소드 정렬에서 누락. 현재 정렬 분류에 누락 항목은 있으나 4-3 불변 조건 확인이 먼저다.
 2 문장 후 반응이 늦음: 문장별 첫 키 지연. 내 누적 중앙값(최근 3세션, 같은 hintOn)의 firstKeyDelayRatio(임시 1.3)배 이상이면 "관찰". 기준선 세션이 3개 미만이면 판정하지 않는다.
 7 키를 두 번 누름: 직전과 같은 물리 키이고 목표가 그 키가 아닌 입력이 duplicateKeyMs(임시 50ms) 안에 일어남. IME 중복 신호는 제외한다. "방금 친 키를 또 누름" 문구에 쓰던 비율은 근거가 약해 쓰지 않는다.
 8 스페이스: 공백 누락(목표 공백에 공백 없이 다음 글자), 초과(목표 글자 위치에 공백), 위치 오류. 현재 집계 항목은 있다.
 10 오타를 제때 안 고침/누적: 고치지 않고 이어서 친 최대 연속 수와 문장당 평균.
 12 한영키를 잘못 누르거나 안 누름: 한/영 상태 오입력 횟수. 문장 첫 입력에서의 불일치와 문장 중간 불일치를 나눈다.
 13 특정 손가락 오타: 손가락별 {k, n} + 묶음 판정(10번). Shift 조합 글자는 뺀다.

Phase 5
 5 손 위치가 너무 멀거나 가까움: 뻗음 구간별 오타율(4-9). 구간별 시도 수가 groupMinSamples 이상일 때만 비교한다.
 6 긴 글에서 오타율이 높음: 세션 안에서 문장 길이 상위 1/3과 하위 1/3의 오타율을 비교한다. 각각 3문장 이상일 때만 판정한다. 태그를 쓰지 않는다.
 11 자음과 모음 순서가 바뀜: 한 음절 안에서 자모 전치. 자모 단위 정렬이 필요하다.
 14 오타가 반복되면 느려짐: 오타 직후 5키 중앙값 간격 / 평소 중앙값 간격이 slowdownRatio(임시 1.3) 이상. 오타 연쇄는 60초 안에 오타 3회 이상. 연쇄 표본이 부족하면 "아직 기록이 적어요"로 둔다.

Phase 6 (키업 기록이 충분히 모인 뒤)
 3 Shift를 제때 떼지 않음: 직전 글자에 Shift를 썼고 다음 글자는 Shift가 필요 없는데 Shift가 눌린 채인 입력. Shift 해제 지연 중앙값도 기록한다.
 4 짧은 글에 성급함: 세션에서 짧은 문장(길이 하위 1/3, 5문장 이상)에서 첫 키 지연이 짧은 쪽 절반이면서 오타율이 평균 이상이면 "관찰"로만 표시한다. 확신도는 항상 "아직 기록이 적어요".
 9 두 키를 동시에 누름: 다음 keydown이 이전 키의 keyup보다 먼저 일어난 비율. keyupCoverage 조건(6-2)을 만족할 때만 판정한다.

[10] 확신도, 묶음, 누적
10-1. 확신도 이름(화면): 아직 기록이 적어요 / 어느 정도 보여요 / 이번 연습에서 뚜렷했어요. 내부 값은 low / mid / high다.
10-2. 계산: 코드가 한다. 설정값은 부록 A.
  - high: 시도 수 ≥ highMinimumSamples(30)이고 Wilson 하한이 세션 전체 오타율보다 큼
  - mid: 시도 수 ≥ mediumMinimumSamples(15)이고 Wilson 하한이 세션 전체 오타율보다 큼
  - low: 그 밖. 시도 수 5 미만은 약점에서 제외한다.
10-3. 묶음 판정: 키 하나가 아니라 4-8의 묶음에도 같은 규칙을 적용한다. 묶음의 최소 시도 수는 groupMinSamples(임시 50). 묶음에서 "어느 정도 보여요" 이상이 나오면 키 하나보다 우선해서 약점 카드로 올린다. [제안]
10-4. 누적: 같은 hintOn인 최근 accumulateSessions(3)개 세션의 {k, n}을 합쳐 같은 규칙으로 다시 판정한다. 화면에 "최근 3번 합산 기준"이라고 표시한다. 세션이 3개 미만이면 지금까지의 세션으로 합산하고 "연습을 N번 더 하면 손가락별 패턴을 볼 수 있어요"를 보여 준다. [제안]
10-5. 이전 연습 비교: 같은 hintOn 세션끼리만 한다. 두 구간이 겹치면 "변화를 단정하기 어려워요"라고 쓰되, 약점 키 전체를 나열하지 않고 변화가 가장 큰 상위 3개와 "3번 연속 높음" 같은 추세만 보여 준다. [제안]
10-6. 약점 카드 최대 2개(mid 이상). low 중 상위 3개는 "지켜볼 것"으로 한 줄씩 보여 준다. 같은 탐지기 유형은 한 세션에 카드 1개. 기준선 세션(3개 미만)에는 카드를 만들지 않고 "지켜볼 것"만 보여 준다. [제안]
10-7. 일반 연습 전환(D15): mid 이상 약점이 하나도 없으면 약점 연습 버튼은 일반 연습을 만든다. 화면: "아직 뚜렷한 약점이 없어서 일반 연습을 준비했어요."

[11] 결과 화면과 용어
11-1. 구성 [제안]
  1) 맨 위 한 줄 요약. 예: "정확도 93%, 분당 277타예요. 뚜렷한 약점은 아직 없어요."
  2) 약점 카드 최대 2개: 제목, 근거(쉬운 말), 가능한 원인 2개 이상, 확인해 볼 방법, 오늘 해볼 연습, "맞아요/아니에요" 버튼.
  3) 지켜볼 것(low) 최대 3개.
  4) 자세히 보기(접힘): 키보드 지도, 키별 오타, 묶음별 표, 이전 연습 비교, 감지 결과, 문장 특성별 속도, 느린 어절, 입력 간격, AI 요약 데이터.
11-2. 용어 바꾸기
  신뢰구간 95% (9~33%) → 실제 오타율은 대략 9~33% 사이로 보여요 (범위가 넓으면 아직 판단하기 어려워요)
  k/n (Wilson 95%) → 38번 누르는 동안 7번 틀렸어요
  확신도 낮음 → 아직 기록이 적어요
  확신도 높음 → 이번 연습에서 뚜렷했어요
  정렬 분류: 누락 0, 초과 79, 치환 5, 전치 1, 모호 0 (n=85) → 틀린 입력 N번 (같은 자리에서 이어진 실수를 묶으면 M번): 빠뜨림 0번, 잘못 더 누름 a번, 다른 키로 바뀜 b번, 순서가 바뀜 c번
  간격 n=915 · 중앙값 139ms · IQR 107ms → 키를 누른 간격의 중간값은 139ms예요. 가운데 절반은 107ms 범위 안에 있어요
  longGap 1회 → 2초 넘게 멈춘 적이 1번 있어요
  집계 안 됨 → 이 기능을 판단하려면 데이터가 더 필요해요
  원시 키 코드 기준 → 사용자 화면에서 삭제
  감속 기준 중앙값 → 평소 입력 속도
  왼손로/오른손로 → 조사 함수로 "왼손으로/오른손으로/엄지로"
11-3. 조사 처리 함수(josa)를 만들어 모든 템플릿 문장에서 쓴다. 테스트: 왼손으로, 오른손으로, 엄지로, 새끼손가락으로.
11-4. 물음표 툴팁: 오타율 구간, 뻗음 거리, 에피소드, 지우기 포함 정확도, 중앙값에 붙인다.
11-5. 로컬 요약 문장 규칙: 관찰한 숫자만 쓴다. "손이 앞서가요", "평균보다 N배"처럼 원인을 단정하거나 비교 기준이 없는 문장은 쓰지 않는다. 방금 친 키를 또 누른 비율은 문구에 쓰지 않는다.
11-6. 라운드 막대 hover는 값이 보이게 유지한다(웹과 Electron 모두).

[12] AI 코치
12-1. 제공자: Gemini(기본), Multi AI(OpenAI 호환 Baze 게이트웨이). 제공자별 키를 Electron safeStorage로 따로 암호화해 저장한다. 키가 없으면 AI 버튼을 끄고 로컬 요약만 보여 준다. [제안]
12-2. 모델 목록: gemini-3.5-flash-lite, gemini-3.8-flash(기존) + Multi AI: gpt-6.2-sol, gpt-6.1-terra, gpt-6-luna, claude-opus-5-5, claude-sonnet-5-5, claude-haiku-5-5, gemini-4-carbon, gemini-4-neon, gemini-4-hydrogen, gemini-4-argon. 기본은 Gemini, 하이쿠는 선택 가능. [제안]
12-3. 역할: 사실은 알고리즘이 만든다. AI는 사실을 쉬운 말로 설명하고 가능한 원인과 확인 방법을 제안한다. AI는 새 숫자를 계산하지 않고, 기준값을 정하지 않고, 확신도를 정하지 않는다.
12-4. 사실 목록: 요약 데이터에서 F01, F02… ID가 붙은 사실을 만든다. 각 사실은 {id, label, k, n, pct, 구간 …}를 가진다.
12-5. 응답 형식(JSON 스키마로 강제):
  headline, strengths[{text, factIds}], weaknesses[{title, factIds, possibleCauses[2개 이상], checkNext, advice}], nextStep
  - 확신도 필드는 AI 응답에 없다. 코드가 factIds로 찾아 붙인다.
12-6. 숫자 규칙 [제안]
  - headline, strengths.text, weaknesses.title과 근거 설명에는 숫자를 직접 쓰지 않고 자리표시자를 쓴다. 예: "{F02.n}번 중 {F02.k}번 틀렸어요".
  - 코드가 자리표시자를 사실 값으로 채운다. 로컬 요약 문장도 같은 렌더러를 쓴다.
  - 자리표시자 밖의 숫자가 있으면 그 문장을 제거한다. advice와 checkNext의 연습 분량(예: "10문장")은 허용한다.
  - 존재하지 않는 factId가 있는 항목은 제거한다. 약점이 모두 제거되면 로컬 요약만 보여 준다.
12-7. 서버와 화면이 같은 응답 형식을 쓴다. 정규화 함수를 한 번 거친 뒤 화면 상태에 넣는다. possibleCauses가 없어도 화면이 깨지지 않는다.
12-8. 하이쿠처럼 작은 모델 대응: 응답은 JSON 스키마로 강제하고, 형식이 틀리면 한 번 재시도한 뒤 로컬 요약으로 돌아간다. [제안]
12-9. 약점 연습 문장 생성
  - 확신도 mid 이상인 약점만 AI에 보낸다. 없으면 일반 연습(D15).
  - 10문장 중 practiceWeakShare(임시 0.7)만큼은 약점 자모 커버리지 점수가 높은 후보를 우선 고르고, 나머지는 일반 문장으로 섞는다. 태그로 문장을 고르지 않는다. [제안]
  - 검사: 허용 문자, 길이(D11), 중복, 세션 총 길이 ±30%(D10). 최대 3회 재시도.
  - focus 문구는 검증된 약점과 맞을 때만 화면에 보여 준다.
12-10. 패턴 후보 제안(AI가 후보를 내고 알고리즘이 묶음 통계로 검증) [예정]
12-11. 사용자가 카드에서 누른 "맞아요/아니에요"는 세션에 저장만 한다. 분석 반영 [예정]

[14] 검증
14-1. 불변 조건 테스트
  - 에피소드 수 ≤ 오입력 수. 정렬 분류 n = 에피소드 수.
  - Backspace는 정렬 분류의 "초과"에 세어지지 않는다.
  - 오타 1개를 낸 뒤 Backspace로 지우고 다시 치는 시나리오: 오입력 1, 에피소드 1, 치환 1, 초과 0, 잘못 지움 0.
  - 오타 없이 정타를 Backspace로 지우는 시나리오: 잘못 지움 1.
  - 오타 뒤에 정타 2개를 더 치고 모두 지운 뒤 다시 치는 시나리오: 잘못 지움 0(필요한 지우기).
  - 낱자 하나 빠짐: 오입력은 여러 건이지만 에피소드 1, 누락 1, 판정용 통계는 first 1건만 센다.
14-2. 감지 시나리오 14개(9번). 항목마다 합성 입력열을 넣고 기대 분류를 확인한다.
14-3. 회귀: 스페이스 중복 버그, 한글 조합 테스트(5번), 라운드 구성 ±30%, 일시정지, AI 응답 정규화.
14-4. 현재 실패하는 테스트와 타입 오류(예: ai.test.ts가 기대하는 evidenceHasOnlySummaryNumbers, confidenceForWeakness 내보내기 불일치, tsc 오류)를 Phase 0에서 정리한다. 정리하지 못하면 이유를 보고한다.
14-5. 사용자 직접 검증 연습(사용자가 한다. Codex는 시나리오 목록만 문서로 만든다): 스페이스 빼고 치기, ㅔ 자리에 ㅖ 치기, 오타를 고치지 않고 넘어가기, Shift를 늦게 떼기, 한/영 상태 틀리기.
14-6. 자동 경고: 목록은 비었는데 횟수가 있는 경우, 합계가 서로 맞지 않는 경우에 개발 로그에 경고를 남긴다.

## 병합 차이 및 확인 목록

아래 항목은 v1.1 개요와 v1.0 세부 명세 사이에서 값이 다르거나, 적용 범위를 추가로 확인해야 하는 지점이다. 코드 변경은 이 병합에 포함하지 않았다.

1. **키보드 종류 선택 UI** — v1.1 §3은 시작 화면에서 데스크톱/노트북 선택을 제공하고 기록에 남긴다고 한다. v1.0 D2는 선택 UI를 없애고 기존 기록의 `keyboard` 필드는 읽기만 하며 분석에 사용하지 않는다고 확정한다. **적용:** D2를 우선한다.
2. **라운드 선택** — v1.1 §3·§8은 기본 30라운드를 서술한다. v1.0 D9는 10/20/30 선택, 기본 30을 확정한다. **적용:** 10/20/30 선택을 제공한다.
3. **약점 카드 개수** — v1.1 §12는 약점 최대 3개라고 한다. v1.0 §10-6·§11-1은 중간 이상 확신도의 카드 최대 2개와 낮은 확신도의 관찰 항목 최대 3개를 구분한다. **적용:** v1.0의 구분된 표시 규칙을 따른다.
4. **태그의 분석·선택 사용** — v1.1 §9는 태그를 약점 요약 및 약점 연습 문장 생성 근거에 쓴다고 한다. v1.0 D13은 태그를 오타 판정, 약점 판정, 문장 선택 기준에 사용하지 않고 표시와 참고용으로만 쓴다고 확정한다. **적용:** 태그를 판정이나 선택 기준으로 쓰지 않는다. v1.1의 “근거”는 설명에 참고하는 용도로 한정한다.
5. **받침많음 표시 기준** — v1.1 §9는 대표 기준을 0.4 이상으로 적었고, v1.0 §16은 0.5를 제안했다. **미확정:** v1.0에도 [제안]으로 기록되어 있으므로 최종 기준을 사용자 확인 항목으로 남긴다. 둘 다 표시용 기준이며 판정에는 쓰지 않는다는 점은 일치한다.
6. **라운드 총 길이 재추첨** — v1.1 §8은 ±30% 범위를 벗어나면 전체를 다시 뽑는다고만 한다. v1.0 D10은 최대 시도 횟수 이후 기준 총합에 가장 가까운 구성을 쓰고 로그를 남긴다고 추가한다. 최대 시도 횟수의 수치는 문서에 없다. **적용/확인:** 실패 시 대체 동작은 D10을 따르며 최대 재시도 횟수는 미정이다.
7. **기록 보관 범위** — v1.1 §5는 최근 최대 8회 기록을 말한다. v1.0 §13-2는 원본 이벤트 8세션과 세션 요약 50세션을 구분한다. **적용:** 원본과 요약의 보관 개수를 별도로 관리한다.
8. **저장 기술** — v1.1 §5는 “브라우저 저장소 형식”이라고 표현하고, v1.0 §13-2는 `localStorage`를 명시한다. 의미상 충돌은 없으나 Windows 앱에서의 실제 저장 위치·용량은 별도 확인이 필요하다. SQLite 전환은 v1.0 §16에 따라 마감 후 검토한다.
9. **설정 기능의 상태** — v1.1 §15는 손목 기준점과 손가락 배정 등을 설정 기능으로 열거하지만, v1.0 §13-1은 상세 설정안을 제시한다. 두 문서 모두 각 항목의 구현 완료 여부를 분명히 구분하지 않는다. **확인 필요:** 실제 구현 여부를 확인 전까지 완료 기능으로 단정하지 않는다.
10. **AI 모델 목록** — v1.1 §14는 Gemini와 Multi AI 제공자만 개괄한다. v1.0 §12-2에는 구체 모델명이 제안으로 열거되어 있다. 충돌보다는 상세 수준 차이다. 모델 목록은 v1.0 제안으로 보존하며, 현재 지원 여부는 코드 확인 항목이다.
11. **문장 특성 태그 기준과 설정 위치** — v1.1 §9는 `tag_rules.txt`와 설정 파일을 기준으로 한다고 한다. v1.0 §7-7은 표시 라벨 기준을 config에 둔다고 한다. 기준의 단일 원천이 둘인지 하나인지 명확하지 않다. **확인 필요:** 같은 기준을 중복 관리하지 않도록 실제 기준 파일을 정리해야 한다.
12. **v1.1의 완료/진행 상태 표현** — v1.1 §17은 일부 기능을 “완료 또는 진행 중”으로 함께 묶어 완료 여부를 특정하지 않는다. v1.0 §0-2는 확인 항목은 코드로 사실을 확인하라고 규정한다. **적용:** 개별 상태는 코드 확인 전까지 미확정으로 둔다.
